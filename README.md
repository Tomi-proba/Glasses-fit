# Glasses Fit

Take a photo, pick a brand, and get sunglasses or eyeglasses recommendations matched to your face shape and the look you're going for — recommending **real, currently-sold models** from a curated product database, never invented ones.

## How it works

1. **Pick a brand** — 8 brands: Ray-Ban, Oakley, Persol, Warby Parker, Gucci, Prada, Tom Ford, Oliver Peoples.
2. **Sunglasses or regular glasses.**
3. **Pick a look** — Everyday, Classic, Flashy, or Sporty (capped at four by design).
4. **Add a photo** — via webcam or file upload. A face-shape estimate (oval, round, square, heart, diamond, or oblong) is computed **entirely in the browser** using on-device face landmark detection ([MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)). No photo is ever uploaded to a server. If detection fails (or you'd rather skip the photo), you can pick your face shape manually.
5. **Results** — brand + type + look filters the real catalog first; face-shape suitability narrows it further; up to **3 concrete real models** come back, each with its real name, real price (when known), a one-sentence reason tied to your specific face shape, and a link to the real product page. If nothing in the real catalog matches, the app says so explicitly instead of inventing a frame.

## Why a "recommendation script" instead of a live LLM call

This is a fully static, client-only app with no backend and no API key anywhere — same as the rest of this project. That means there's no safe way to call an LLM with a "system prompt" at runtime (an API key shipped to the browser would leak). Instead, the constraint the brief asked for — *only ever recommend a real product from the list, and say so explicitly when there's no match* — is enforced by **deterministic filtering code** (`src/lib/recommend.ts`), which is a stronger guarantee than a prompt: it's structurally impossible for it to return anything not in `products.json`.

## Where the product data comes from

`src/data/products.json` is generated by `scripts/generate-products.mjs` from real models gathered via web research. Two honest caveats from that research, both flagged rather than papered over:

- **No live page scraping.** This environment's page-fetching tool is blocked by network policy for arbitrary sites, so data comes from search-result snippets (real names, prices, and source URLs) plus well-documented public knowledge of long-established, iconic model lines — never invented. Every product's `productUrl` is a real page.
- **No verified hotlinkable photos.** Direct product image URLs couldn't be confirmed without page-fetching, so `image` is `null` for every product — the app keeps using its procedural SVG glyph (`src/components/FrameGlyph.tsx`) for the on-screen icon, and the "View real product" link takes you to the real page for actual photos.
- **Per-brand shortfalls are reported, not padded.** The brief asked for ~20 verified real models per brand; where research didn't reach 20, `generate-products.mjs` prints a warning instead of filling the gap with made-up models:

  ```
  rayban: 20/20 ✓
  oakley: 20/20 ✓
  persol: only 10/20 verified real models found — NOT padded with invented data
  warbyparker: 20/20 ✓
  gucci: only 4/20 verified real models found — NOT padded with invented data
  prada: only 8/20 verified real models found — NOT padded with invented data
  tomford: 20/20 ✓
  oliverpeoples: only 14/20 verified real models found — NOT padded with invented data
  ```

  Regenerate with `npm run generate-products` (only needed if you edit the curated list in the script — the committed `products.json` is already up to date).

The face-shape → frame-shape matching follows standard optician heuristics (e.g. angular frames for round faces, rounded frames for square faces), and the specific one-sentence reasons per (frame shape, face shape) pair, live in `src/data/faceShapeFit.ts`.

## Stack

- React + TypeScript + Vite
- Tailwind CSS
- `@mediapipe/tasks-vision` for on-device face landmark detection — the WASM runtime and model weights are self-hosted under `public/mediapipe` and `public/models` so detection works fully offline and without any third-party CDN dependency.

## Development

```bash
npm install
npm run dev                 # start dev server
npm run build                # typecheck + production build
npm run lint                  # oxlint
npm run generate-products      # regenerate src/data/products.json from scripts/generate-products.mjs
```

## Project structure

```
src/
  types.ts                  shared types (Frame, ProductRecord, ...)
  data/
    brands.ts                brand list (8 brands)
    looks.ts                  the 4 "look" options
    faceShapeFit.ts            face-shape ↔ frame-shape heuristics + per-pair reasons
    products.json               generated real product data (see scripts/generate-products.mjs)
    catalog.ts                  maps products.json → the app's Frame shape
  lib/
    faceShape.ts               on-device face landmark detection + shape classification
    recommend.ts                 real-catalog-only filtering logic, capped at 3 picks
  components/                    step screens + UI
scripts/
  generate-products.mjs           curated real product list → products.json, with shortfall warnings
```
